## 三、你第一次上电要按这个顺序（顺序错了会白折腾）

1. **先只插网线 + 5V 供电**，不插 USB。IOB 底板插上后 **USB-NCM 会失效**，只能走网口。
2. Duo 默认 `192.168.0.233`（IOB 出厂值，若与现场网段不同，先用串口线 CH340 进 `vi /etc/init.d/S99network` 或 `/etc/network/interfaces` 临时改到 `.5` 段），确认能 ping 到网关。
3. **改 hostname**：A 板 `milkv-a`、B 板 `milkv-b`（`/etc/hostname` + `/etc/hosts` 两处都要改），否则 `ssh` 分不清谁是谁。
4. 把两块板 MAC 抄下来（`ip link show eth0`），交给 A 在路由器里绑 `.7` / `.8`。
5. 绑完**断电重上电**，`ping 192.168.5.7` + `ssh root@192.168.5.7` 双证，截图存到节点手册。
6. 板内**不要**再写死静态 IP——写死了换场地就得重刷，答辩现场没时间。

## 四、桥接脚本与看板的对接口径（别自己发明字段）

`duo_bridge.py` 往 `http://192.168.5.20:8000/ingest` POST JSON。D 的看板监听 `0.0.0.0:8000`。
你这边只需保证三件事：

- **端口可配**：`SERVER` 允许被环境变量覆盖（`os.environ.get("DASH_URL", SERVER)`），答辩现场改 IP 不用改代码。
- **失败不阻塞**：`requests.post(..., timeout=2)`，异常 `except` 后继续采下一帧，不要让网络抖动把采集停了。
- **心跳先行**：先发 `{"type":"heartbeat"}` 再发数据帧，D 的"数据完整性看板"靠心跳算缺帧率。

## 五、蜂鸣器这件事与你无关，但有一个坑要避开

声学报警在 **UNO 侧**（`D4` 有源蜂鸣器，节奏编码：危险 1.5 s 周期、注意 3 s 周期）。**Duo 不要去拉 GPIO 驱动蜂鸣器**，两块板的 IO 不在一个电平域，也不该让网络抖动决定响不响。

你要做的是：把报警事件作为**事件类型**上报（`hazard` / `caution` / `deny` + `ts`），让 D 在时间线上标出来。**不要在 JSON 里放 `freq_hz`**——现在没有音调这回事了。
