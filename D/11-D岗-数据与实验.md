## 四、CSV schema（契约 3 底稿）

### `data/exp1/exp1_<arch>_n<k>_run<i>.csv`（实验一：架构 × 节点数）

| 列 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `ts` | float | s（Unix） | 起始时间戳，**统一取 PC 时钟** |
| `arch` | enum | — | `alpha`（边缘推理）/ `beta`（中心推理） |
| `n_nodes` | int | — | 1 / 2 |
| `run` | int | — | 第几次重复 |
| `tx_bytes` | int | B | 60 s 内上行字节差（`/proc/net/dev`） |
| `bw_Bps` | float | B/s | `tx_bytes / 60` |
| `infer_ms` | float | ms | 单帧推理耗时（α=PC 中心推理，β=Duo 边缘推理） |
| `lat_ms` | float | ms | 端到端（采集→出结论） |
| `pc_cpu_pct` | float | % | PC 侧 60 s 平均 CPU |
| `duo_cpu_pct` | float | % | 节点侧 60 s 平均 CPU |
| `dropped` | int | 帧 | 桥接队列丢帧数（B 提供） |
| `note` | str | — | 异常备注 |

### `data/exp2/exp2_g<group>_<light>_<dist>_<density>_run<i>.csv`（实验二：视觉计数）

| 列 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `ts` | float | s | 起始时间戳 |
| `group` | int | — | 组号 1–12 |
| `light` | enum | — | 光照水平（按 `04 §3.3`） |
| `dist` | float | m | 距离水平 |
| `density` | enum | — | 通过方式（单人走 / 连走两人） |
| `truth` | int | 人 | **人工真值**（当场记，不许事后回忆） |
| `auto` | int | 人 | 光电通道计数（`@C` 末值 − 初值） |
| `miss` | int | 人 | `truth - auto`（负数为误检） |
| `photo_events` | int | 次 | 遮挡沿次数 |
| `note` | str | — | 如"间隔<3 s，可能合并" |

**通用规矩**：
- 时间戳一律 PC 侧 `time.time()`，**不要在板上取时间**（两块板时钟不同，没法对齐）
- 缺失写 `NA`，不写 0、不空着
- 每个实验目录下放一个 `README.txt`，写"谁在哪天用什么配置采的"

## 五、三个实验怎么跑

### 实验一 · 架构 × 节点数（4 组）

- 因子：架构 **α（集中式 / 中心推理，对照组）** 与 **β（分布式 / 边缘推理，本系统）** × N ∈ {1, 2}
- 每组 **≥3 次重复**，每次 60 s
- 每组记录：上行带宽、端到端延迟、PC CPU、节点 CPU
- **同一时段只跑一种架构**，否则曲线会混（这条在 `07 §六` 的板时表里已写死）
- 硬件只有 2 块板 → 只能测 N=1 与 N=2；报告里如实写"补第 3 块后追加"，`01 §0` 已经这么承诺过

### 实验二 · 视觉计数（12 组 × 10 人次）

- 三个因子按 `04 §3.3`（**光照 3 水平 × 2 × 2 = 12 组**，具体水平值 D1 就抄进记录表，别到现场再想）
- 每组 10 人次，共 120 人次
- **真值当场记**：人走过去同时按一下计数器/在表上划一笔。事后凭记忆补的真值等于假数据
- 关键指标：`准确率 = 1 − Σ|miss| / Σtruth`，同时报漏检率与误检率
- 已知风险（`04 §6` 已认）：连走两人时若间隔 <3 s，光电只数 1 个 → 该组要在 `note` 标注，**不许悄悄剔除**

### 实验三 · 防尾随（加分项，时间够再做）

一次合法刷卡 + 紧随 1 人进入 → 系统应报警。10 次试验，记成功率与误报率。

## 六、看板（`dashboard\`）

三个页面，**优先级从高到低**：

1. **节点状态**：A/B 在线/离线、最后心跳、当前等级（0/1/2）、门磁状态
2. **实时曲线**：温度/烟雾/火焰三路 rolling 5 min
3. **报警时间线**：`@A` 事件列表，带时间与来源（NONE/SMOKE/FLAME/TEMP）

技术选型随意（Flask + 静态 HTML 即可，能跑就行），但必须做到：
- 从 `duo_bridge.py` 的 `SERVER` 端点收 POST（`/ingest`）
- 数据落 `data/raw/` 的同时进内存，刷新页面不掉
- **断线时显示"节点离线 + 最后心跳时间"**，不要静默空白（这是"边缘自治"叙事的可视化证据）

> D1–D4 用 mock 数据做：造一个 `mock_feed.py`，每 2 s 生成一条假 `@E`。**不要等 B。**

## 七、报告要的 5 张图（先想清楚，再采集）

| # | 图 | 轴 | 结论想说什么 |
|---|---|---|---|
| 1 | **带宽 vs 节点数** ★核心 | x=节点数，y=上行 B/s，两条线 α/β | **α（推流）线性涨，β（传结论）几乎平** |
| 2 | 中心负载 vs 节点数 | x=节点数，y=PC CPU % | **α 迅速顶满（N 路解码+推理），β 只有聚合开销** |
| 3 | 端到端延迟分布 | 箱线图，α/β 各一 | **β 稳定且低（本地推理），α 有长尾（上行排队+中心排队）** |
| 4 | 计数准确率 vs 光照/距离 | 分组柱状 | 侧逆光掉点，需要补光 |
| 5 | 断链报警时延 | 10 次散点 + 中位数线 | 本地判定不依赖链路 |

每张图必须有：坐标轴标签带单位、样本量 n、采集日期。**没有 n 的图在答辩时会被问穿。**
