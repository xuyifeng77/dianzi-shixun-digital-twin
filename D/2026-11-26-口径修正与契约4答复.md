## 二、契约 4 三问：答复 B

B 的三问（11-26 留言）：①`node` 用 nodeA/nodeB 还是别的命名 ②`env` 是字符串，谁转数字 ③`count:null` 接不接受。

**1）`node` 用 `nodeA` / `nodeB` / `nodeC` / `nodeD`**，小写、无空格、无前缀。
- 依据：契约 5（A）定的 hostname 唯一；契约 3 事件表 `node_id` 列也要填这个值；看板的 `NODE_IPS` 键也是这四个。
- 不要再出现 `node1`、`A`、`duo-a` 之类别名；bridge 的 `NODE` 环境变量取值必须落在这四个里，否则看板会把帧丢掉（现行为：未知 node 只记日志不落卡）。

**2）`env` 数值由 bridge 转成数字**，D 侧不自作主张。
- `t`/`h` → float（1 位小数）；`smoke`/`flame`/`light`/`sound` → int。
- 原因：契约 3 的 `exp1` 表要算均值、看板要画曲线，字符串会让下游每处都写一遍 `float()`；类型错误应该在一个地方暴露（bridge），而不是散落在 CSV 与前端。
- 但**"缺失"和 `0` 必须能区分**：缺测写 `null`，不要写 `0`、也不要写 `""`。`0` 是"测到了，值是 0"（比如没烟），`null` 是"没测"。
- D 侧兼容：`app.py` 的 `num()` 已经把 `""`/`null`/`NA`/`-` 都当缺失，所以你真按数字转了，我这边不用改代码。

**3）`count: null` 接受**，语义 = "本次上电以来**从未**检测到人"，与 `0`（检测到过、当前 0 人）不同。
- 落 CSV：`null` → `NA`（契约 3 通用缺失记法）；`0` 照写 `0`。
- 看板：`null` 显示 `—`，不显示 `0`，避免答辩时被问"这里 0 人还是没数据"。
