## 1. 传输

| 项 | 规定 |
|---|---|
| 协议 | HTTP/1.1 `POST`，`Content-Type: application/json`，UTF-8，**一帧一请求**（不批量、不换行分隔） |
| 目标 | `http://<PC实测IP>:8000/ingest`；**默认值必须是 `192.168.5.20`**（v1.5 现为 `192.168.5.5`，**错**，最迟 11-27 改） |
| 超时 / 重试 | 单次 `POST` 超时 **2 s**；失败重试 3 次（间隔 0.2 / 0.5 / 1.0 s），仍失败则丢弃并 `failed += 1` |
| 断线行为 | **不阻塞串口读线程**：队列上限 200 帧，满则丢最旧并 `dropped += 1`；连续 3 次失败置 `link=dead`，但继续按 10 s 发心跳试探 |
| 应答 | 看板返回 `{"ok":true,...}`；bridge **不得依赖应答内容**（只用于计数） |

## 2. 公共字段（每帧必备）

| 字段 | 类型 | 规定 |
|---|---|---|
| `type` | string | **只取 7 个值**：`env` / `alarm` / `count` / `door` / `rfid` / `infer` / `heartbeat`。看板**必须忽略未知 `type` 而不报错**（为后续扩展留口） |
| `node` | string | **只取契约 5 的 `milky-a` / `milky-b` / `milky-c` / `milky-d`**。v1.5 的 `NODE` 白名单现只认 `nodeA…nodeD`，**必须改成 `milky-*`**（旧名由看板 `norm_node()` 兜底，但不应依赖兜底） |
| `ts` | number | **节点钟**：ntpd 校时后的 UTC epoch 秒，3 位小数。**落 CSV 不用它**（契约 3 规定 `ts` = 看板收到时刻 `ts_rx`），只存 `ts_node` 与 `skew_s` 作诊断。节点偏差 >1 s 时实验前必须校时 |
| `sim` / `ts_pc` | — | **仅 mock 用**（`mock_feed.py`）；真流禁止出现，看板见 `sim` 才认 `ts_pc` 作时间 |

## 3. 七类帧

### 3.1 `env`（环境，`@E`，**2 s / 帧**）

```json
{"type":"env","node":"milky-a","ts":1795699200.123,
 "t":24.2,"h":45.0,"smoke":12,"flame":4,"light":78,"sound":6,"rst":0}
```

| 字段 | 类型 | 单位 / 范围 | 缺测 |
|---|---|---|---|
| `t` | number | ℃ | `null` |
| `h` | number | %RH | `null` |
| `smoke` / `flame` / `light` / `sound` | integer | ADC 0–1023 | `null` |
| `rst` | integer | 复位原因码（固件 `resetCause`），可选 | 省略 |

> 数值化由 **bridge 侧**完成：`""` / `"nan"` / `"na"` / `"null"` / `"inf"` 一律转 `null`（固件 DHT 读失败会打 `nan` 字符串，原样入库会毁整列均值）。**不允许把数字写成字符串**（`"24.2"` 不合格）。

### 3.2 `alarm`（报警，`@A`，事件驱动）

```json
{"type":"alarm","node":"milky-a","ts":1795699300.5,"args":[2,"SMOKE"]}
```

- `args[0]` = `lv` ∈ `{0,1,2}`（0=解除，1=注意，2=危险），越界归 0；
- `args[1]` = `src` ∈ `{NONE,SMOKE,FLAME,TEMP}`，未知归 `NONE`；
- **归一化在 bridge 侧做**，CSV 侧不再防御；
- 只在 `lv` 变化时上报（同等级重复不刷帧）。

### 3.3 `count`（人次，`@C`）

```json
{"type":"count","node":"milky-b","ts":1795699400.2,"passes":37}
```

- `passes`：**累计人次**（uint16，节点上电清零）；
- 看板按差分算"本组人次"，`passes` 回退即判节点重启并重开本组；
- **不得**改成"每帧增量"（差分逻辑已在看板与 `clean.py` 落地）。

### 3.4 `door`（门磁，`@D`）

```json
{"type":"door","node":"milky-a","ts":1795699500.7,"open":1}
```

- `open` ∈ `{0,1}`；**只更新状态页，不进事件表**；门磁**不参与判级**（契约 3 §6.1 已删"门磁强开"触发项）。

### 3.5 `rfid`（刷卡，`@R`）

```json
{"type":"rfid","node":"milky-a","ts":1795699600.4,"uid":"DEADBEEF","ok":false,"pattern_ms":"80x2/400"}
```

- `uid`：8 位大写十六进制；
- `ok`：`true` 授权 / `false` 拒绝；
- `pattern_ms`：**只接受 `80x2/400`**（A 的 D-01 决策 + 契约 3 §6.1）。v1.5 现在发 `"80/120"`，**必须改**；改前看板会丢弃该值并按 `80x2/400` 落表，同时 `pattern_warn += 1`。

### 3.6 `infer`（推理，契约 4 新增，**不落事件表**）

```json
{"type":"infer","node":"milky-b","ts":1795699700.9, ...}
```

- 字段由 B 在 **契约 4.1**（视觉推理结果）里定，本版先只保证：**带 `node`/`ts`、`type=infer` 可被看板忽略并计入 `frames_rx`**；
- 现有 208 条真样本**只有这一类**，D5 联调前必须补齐其余 6 类的真样本（见 §8）。

### 3.7 `heartbeat`（保活，`@Q`，**10 s 一次**）

```json
{"type":"heartbeat","node":"milky-a","ts":1795699800.1,"link":"ok","dropped":0,"failed":0}
```

- `link` ∈ `{boot,ok,dead}`；`boot` 表示 bridge 刚启动；
- `dropped` / `failed` 是 **bridge 队列 / POST 层**计数，**不是** `@E` 帧级丢包（`loss_pct` 由看板按 `frames_expected` 算），两者不得混算；
- 看板：**6 s** 无新 `env` 判"链路异常"，**30 s** 判"离线"；`link=dead` 可在 6 s 内提前标异常。

## 4. 频率与带宽

| 帧 | 频率 | 备注 |
|---|---|---|
| `env` | **2 s / 帧**（固件固定） | 契约 3 §1.1 的唯一口径；禁改 1 s/帧 |
| `heartbeat` | **10 s** | 对应 `@Q` 拉帧保活 |
| `alarm` / `count` / `door` / `rfid` | 事件驱动 | `alarm` 只在变级时发 |
| `infer` | ≤ 视频帧率 | 不落事件表，不参与带宽基线 |

> β 带宽口径：v1.5 实测 **55–75 B/s**（旧 150–300 作废）；换 v1.5 后必须重测，`exp1` 的 `note` 写 `#bridge=v1.5`。

## 5. 禁止项（写进代码注释，别靠记）

1. `DASH_URL` 默认值不是 `.20` → **禁止**（现为 `.5`）；
2. `node` 白名单不是 `milky-*` → **禁止**（现为 `nodeA…nodeD`）；
3. `pattern_ms` 出现 `80/120` 之类非契约节奏 → **禁止**；
4. 覆盖 `duo_bridge.py` → **禁止**（`A/06` 按行号引用它；新版本必须另起文件名，现为 `_v1_5`）；
5. 数字写成字符串、缺测写 `0` 或空串 → **禁止**（用 `null`）。

## 6. 看板侧的对应义务（D）

- 未知 `type` / 未知字段忽略不报错；`null` 显示为 `—`；
- 事件表只按契约 3 §6.2 映射写行（`deny` 不进 `@A`、`door` 不进事件表、`infer` 暂存内存）；
- 节点名归一只在收帧口做（`norm_node()`），落盘一律写归一后的值。
