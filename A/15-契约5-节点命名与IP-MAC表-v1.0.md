## 一、节点命名（名字只此一套）

| 角色 | hostname | `node_id`（进 CSV / 看板 / 日志） | 允许写法 | 禁止写法（只许出现在溯源段落） |
|---|---|---|---|---|
| A 板（架构样板 / UNO 主控侧） | `milky-a` | `milky-a` | `milky-a` | `nodeA`、`milkv-a`、`A板`、`node_a` |
| B 板（视觉节点） | `milky-b` | `milky-b` | `milky-b` | `nodeB`、`milkv-b`、`B板`、`node_b` |
| C 板（扩展位，未上板） | `milky-c` | `milky-c` | `milky-c` | `nodeC`、`milkv-c` |
| D 板（扩展位，未上板） | `milky-d` | `milky-d` | `milky-d` | `nodeD`、`milkv-d` |
| PC（看板 + 协调层） | 不设（用 `hostname` 会随机器变） | — | 只用 IP 指代 | `server`、`master`、`localhost` 当节点名 |

- **命名规则一句话**：`milky-` + 单个小写字母（`a`/`b`/`c`/`d`），**全小写、无下划线、无数字**。
- `node_id` 是**枚举**，只允许上表四个值——这是与 [`D/契约3 §1.1`](../D/契约3-实验数据CSV-schema-v1.1.md) 唯一交接口，D 的 CSV 列与看板一律照抄，不另起别名。

## 二、地址与 MAC（照抄，不要自己换算）

| 角色 | hostname | MAC | IP | 端口 | 网关 |
|---|---|---|---|---|---|
| A 板 | `milky-a` | `02:01:0a:00:00:0a` | **`192.168.5.9`** | — | `192.168.5.1` |
| B 板 | `milky-b` | `02:01:0b:00:00:0b` | **`192.168.5.10`** | — | `192.168.5.1` |
| C 板 | `milky-c` | 上板后补（见 §2.2 派生规则） | `192.168.5.11`（顺延） | — | `192.168.5.1` |
| D 板 | `milky-d` | 上板后补（同上） | `192.168.5.12`（顺延） | — | `192.168.5.1` |
| PC 看板 | — | — | `192.168.5.20`（**计划值**；D 的实测（D-1）截至 11-27 未回，11-28 前仍未回则报告按计划值写并注明"未实测"） | **`8000`** | `192.168.5.1` |

**记法**：A 九、B 十、C 十一、D 十二、PC 二十，网关一点一；网段 `192.168.5.0/24`。

### 2.1 写法硬规矩

1. IP **必须四段写全**（`192.168.5.9`），不许写 `.9`、`5.9`、`192.168.05.09`。
2. 端口**必须带**：`192.168.5.20:8000`。桥接 `duo_bridge.py` 的 `SERVER` 与看板监听地址必须是同一个字面量。
3. 看板监听**必须** `0.0.0.0:8000`；写 `127.0.0.1` 等于只有本机能连，B 板上报会全灭。
4. PC 的 `.20` 目前是**暂记值**：D 实测若不符，按 §7 升 v0.1，同步改 `契约3 §1.1` + `duo_bridge.py L11` + 看板启动命令三处，**不要各自偷偷改一行代码了事**。

### 2.2 MAC 派生规则（C/D 上板时照此推）

```
02:01:0<x>:00:00:0<x>      x = 节点字母本身（a/b/c/d），十六进制小写
```

已实测：`milky-a` = `02:01:0a:00:00:0a`、`milky-b` = `02:01:0b:00:00:0b`。C/D 按此规则应分别为 `…0c…0c` / `…0d…0d`，**上板后必须用 `ip link show eth0` 读实际 MAC 核对**，读出不同就登记实际值（v+0.1），不要"按规则应该是"就写进表。

| 是否挂板 | **不挂任何板**（A/B 两板的 USB-A 在正式路线里空置） | [`16`](16-决策记录-D4-三条口径.md) D4-01 |
| ③ 的状态 | **未验证**（T2/T3/T4 无一实测）；只有 11-27 12:00 前三项全过才改判 | `16` D4-01 的翻案口 |

## 三、用方各要遵守什么（签的就是这一节）

### B（视觉节点）
1. 本机 hostname 写 `milky-b`，IP `192.168.5.10`——路由器按 MAC 静态绑定，**板上不配静态 IP**，走 DHCP 拿保留地址。
2. `duo_bridge.py` 的 `SERVER` = `http://192.168.5.20:8000/ingest`，端口 8000 不得省。
3. B 板验收命令用 **`.9`**（A 板）与 **`.10`**（自己），例如 `ssh root@192.168.5.9`、`ping -c3 192.168.5.20`。
4. 上报帧里的节点标识用 `milky-b`，不用 `nodeB`。

### D（数据与实验）
1. CSV `node_id` 列只取 §一 四个枚举值；看板表格/图例显示同样字面量。
2. 看板与入库服务监听 `0.0.0.0:8000`，PC 实际 IP 由 D 用 `ipconfig` / `ip -4 addr` 实测后回填本文 §二（`.20` 那一格）。
3. 文档、答辩 PPT 里出现 `.7/.8`、`nodeA…nodeD`、`milkv-*` 即为**口径错误**，扫描命令见 §5。

## 四、边界与失败行为（漂了怎么认）

| 现象 | 判据 | 谁处理 | 动作 |
|---|---|---|---|
| 板子拿到 `.1xx` 之类非保留地址 | `ip -4 addr show eth0` 与 §二 不符 | 该板所属岗 | 先查 MAC 是否与 §二 一致（`ip link show eth0`）；MAC 变了 = 路由器绑定失效，按 §7 登记新 MAC；MAC 没变 = 路由器规则被删，重绑即可，**本文不动** |
| 两台机器抢同一 IP | `arping -D` 有应答 / 看板出现两台同 `node_id` | A 判 | 后上线的那台先改回 DHCP 重取，禁止"谁先占谁用" |
| PC 换机器 / 换网卡 | `192.168.5.20` 不再属于看板 | D | 重新绑定 + 按 §7 升版本（IP 属冻结项） |
| 板子换新（硬件替换） | 新 MAC | 该岗 | 新 MAC 登记进 §二 并升 v0.1；**旧行不删**，加"已于某日停用" |
| 断网 / 链路丢失 | 节点 6 s 无新帧＝"链路异常"，30 s＝"离线" | B、D | 这是链路口径，不在本契约改判范围内；本文只管"地址没漂" |

## 五、校验命令（谁用谁跑，30 秒能核完）

```bash
# 板侧（root@milky-a / milky-b）
hostname                      # 期望 milky-a / milky-b
ip -4 addr show eth0          # 期望 192.168.5.9 / .10
ip route | grep default       # 期望 default via 192.168.5.1
ip neigh | grep 192.168.5.20  # 期望能看到 PC 的 MAC

# PC 侧（Windows PowerShell）
ipconfig | Select-String 192.168.5
Test-NetConnection 192.168.5.9  -Port 22
Test-NetConnection 192.168.5.10 -Port 22
Test-NetConnection 192.168.5.20 -Port 8000

# 全仓库旧口径扫描（应只剩溯源段落）
rg -n '192\.168\.5\.(7|8)|node[ABCD]|milkv-[ab]' -g '*.md'
```
