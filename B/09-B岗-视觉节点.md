## 五、`duo_bridge.py` v1.2（整份替换，已修三处缺陷）

修了什么：**① 端口探测改成"试探回 `@`"**（本项目这块是 **CH340 克隆板**，Linux 上是 `/dev/ttyUSB0`；16U2 原装板才是 `/dev/ttyACM0`，所以不能靠名字猜）；**② 心跳前置**（原版 `continue` 让 `@Q` 永远发不出去）；**③ 上报走队列线程**（原版 `urlopen` 阻塞串口循环最多 2 s，`@E` 每 2 s 一帧必丢）。

```python
#!/usr/bin/env python3
# duo_bridge.py v1.2  —— 链路口径：ASCII 行帧，无校验（已知取舍，见 06 §P0-3）
import glob, json, queue, threading, time, urllib.request
import serial

SERVER       = "http://192.168.5.20:8000/ingest"   # PC 看板（192.168.5.x 网段，按现场 PC 实际 IP 改）
CARDS        = {"A1B2C3D4"}     # 白名单（边缘判定，断网也能开）
BAUD         = 115200
LOCK_MS      = 3000
HB_INTERVAL  = 10               # 每 10 s 问一次
HB_TIMEOUT   = 35               # 35 s 无回执判死

def pick_port():
    """CH340 克隆板 → ttyUSB*；16U2 原装板 → ttyACM*。逐个探：谁会回 @ 帧就是它。"""
    cands = sorted(glob.glob("/dev/ttyACM*")) + sorted(glob.glob("/dev/ttyUSB*"))
    for p in cands:
        try:
            with serial.Serial(p, BAUD, timeout=1) as s:
                s.write(b"@Q\n"); time.sleep(0.3)
                if s.read(64).startswith(b"@"):
                    return p
        except Exception:
            pass
    raise SystemExit("未找到会回 @ 帧的串口：确认是数据线、Duo 已切 host 模式、chmod 666")

def post(path, obj):
    body = json.dumps(obj, ensure_ascii=False).encode()
    req  = urllib.request.Request(path, data=body,
                                  headers={"Content-Type": "application/json"})
    urllib.request.urlopen(req, timeout=2).read()

_q, _dropped = queue.Queue(maxsize=64), 0

def _worker():
    while True:
        path, obj = _q.get()
        try: post(path, obj)
        except Exception as e: print("[post]", e)
        finally: _q.task_done()

def enqueue(path, obj):
    global _dropped
    if _q.full():
        try: _q.get_nowait(); _dropped += 1
        except queue.Empty: pass
    _q.put((path, obj))

def send(ser, s):
    ser.write((s + "\n").encode())

def _num(s, cast=float):
    """固件在温湿度未就绪时会发 nan（UNO_Node.ino:80 的 env 初值就是 NAN）。
    NaN 直接进 json 会变成 NaN 字面量 —— 非法 JSON，浏览器 JSON.parse 直接抛错。
    也不要原样转发字符串：前端拿到 "nan"/"23.5" 当 number 用会静默出错。
    统一：NaN/Inf → null，其余转成真正的数字。"""
    t = s.strip().lower()
    if t in ("nan", "inf", "-inf", "none", ""): return None
    try: return cast(float(t))
    except ValueError: return None

def main():
    threading.Thread(target=_worker, daemon=True).start()
    port = pick_port(); print("[port]", port)
    ser  = serial.Serial(port, BAUD, timeout=0.2)
    time.sleep(2); ser.reset_input_buffer()

    last_rx = time.time(); last_hb = 0.0; dead = False
    while True:
        now = time.time()

        # ④ 心跳必须先于任何 continue —— 这是 v1.1 的最大 bug
        if now - last_hb >= HB_INTERVAL:
            last_hb = now
            if now - last_rx > HB_TIMEOUT:
                if not dead: print("[LINK] DEAD  (%.0fs 无回执)" % (now - last_rx)); dead = True
            send(ser, "@Q")

        raw = ser.readline().decode("utf-8", "ignore").strip()
        if not raw: continue
        last_rx = now; dead = False
        if not raw.startswith("@"): continue

        f = raw[1:].split(",")
        tag = f[0]

        if tag == "E" and len(f) >= 7:
            # 字段顺序以 C 的契约 1 冻结版为准：@E,温度,湿度,烟雾,火焰,光照,声音
            enqueue(SERVER, {"type": "env", "node": "nodeA", "ts": round(now, 3),
                             "t":     _num(f[1]),          # 未就绪时为 null，不是 "nan"
                             "h":     _num(f[2]),
                             "smoke": _num(f[3], int),
                             "flame": _num(f[4], int),
                             "light": _num(f[5], int),
                             "sound": _num(f[6], int)})
        elif tag == "A" and len(f) >= 3:
            enqueue(SERVER, {"type": "alarm", "node": "nodeA", "ts": round(now, 3),
                             "level": int(f[1]), "src": f[2]})
        elif tag == "C" and len(f) >= 2:
            enqueue(SERVER, {"type": "count", "node": "nodeA", "ts": round(now, 3),
                             "passes": int(f[1])})
        elif tag == "D" and len(f) >= 2:
            enqueue(SERVER, {"type": "door", "node": "nodeA", "ts": round(now, 3),
                             "open": int(f[1])})
        elif tag == "R" and len(f) >= 2:
            uid = f[1].strip()
            ok  = uid in CARDS
            print("[RFID]", uid, "ALLOW" if ok else "DENY")
            send(ser, "@L,%d" % (LOCK_MS if ok else 0))
            enqueue(SERVER, {"type": "rfid", "node": "nodeA", "ts": round(now, 3),
                             "uid": uid, "ok": ok})

if __name__ == "__main__":
    main()
```

**上机自测**（缺一不可）：
1. 拔掉 UNO 的 USB → 35 s 内必须打印 `[LINK] DEAD`，且**不能崩**
2. 把 `SERVER` 改成一个不存在的地址 → `@E` 仍能被解析，只是 `[post]` 报错，串口不卡
3. 插回 → 自动恢复，`[LINK] DEAD` 不再重复打印

## 六、α/β 两套采集程序（实验一的执行体）

| 架构 | 走法 | 我的程序做什么 | 记录什么 |
|---|---|---|---|
| **α 集中式** | Duo 只推流，PC 侧拉流推理（对照组） | 起 RTSP 推流进程，不做推理 | 上行字节数（显著大）/ PC 侧负载 |
| **β 分布式（边缘）** | Duo 本地跑 TDL，只上传结论（本系统） | 推理循环 + 每 2 s 上报 `{count, conf, infer_ms}` | 上行字节数 / 推理耗时 / CPU |

> 📌 **α/β 口径（2026-11-23 统一，以 A 岗 `01 §1.4` / `02 §4.3` / `04 §2.1` 为准）**：**α = 集中式（节点推流、PC 推理，对照组）**；**β = 分布式 / 边缘（节点本地推理、只传结论，本系统）**。本文档早前把两者写反（α=边缘、β=中心），已按此改正；`契约 3` 的 `lat_pipe_ms`「仅 β 组测（节点出结论 → PC 收到）」也印证这一方向。改动记录见 [`15-矛盾排查-2026-11-23`](../共享/15-矛盾排查-2026-11-23.md)。

> 具体二进制名以镜像与官方 SDK 为准：`sample_vi_fd`（Duo 自带示例，打印人脸数）与 TDL SDK 的 `cvi_tdl` 系列示例。**不要照抄网上 CV1800B 教程的路径与模型名。**
> 若镜像无 RTSP 示例，退路：`ffmpeg` 直推（Duo 的 VI 管线不一定走 `/dev/video0`，先确认）。

**带宽怎么测**（同一口径，A 会来核）：
```bash
# 跑 60 s，取两次计数器差值
cat /proc/net/dev | grep -E 'wlan|eth'
sleep 60
cat /proc/net/dev | grep -E 'wlan|eth'
```
记录 `TX bytes / 60` 即上行带宽（B/s）。

## 九、我的风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 模型型号下错 | 推理输出全是垃圾或直接 abort | 只认 `sg200x` / `duo256m` 字样；文件名带 `scrfd_768_432` |
| host 模式折腾掉两天 | `ls /dev/tty*` 一直空 | **2 小时不成就报 A 切方案 ②**，别自己加时 |
| 内存被吃光 | `free -m` 可用 <20 MB，进程被 kill | 关掉不用的服务；推理只开一路；别装 pip 包 |
| 两块板配置不一致 | A 能跑 B 不能 | 每次改完 `cp` 一份配置到 PC，B 板照抄 |
| 网络抖动导致数据缺口 | 实验数据缺帧 | 桥接已带队列与丢帧计数，把丢弃数写进实验记录（这是证据不是污点） |
