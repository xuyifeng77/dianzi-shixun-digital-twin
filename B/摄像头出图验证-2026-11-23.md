## 二、这一步为什么关键

排线、MIPI 通路、sensor 供电、镜像自带的 GC2083 驱动——**任一环错都不出图**。出图即同时证明这四件事都对上了。

> 本记录更进一步：**出图 + 检测框同时出现**，说明"VI 取帧 → NPU 推理 → VENC 编码 → RTSP 推流"整条链路是通的，
> 而不只是"驱动挂上了"。

## 三、复现步骤（别人照做也能出图）

### 3.1 硬件三点

1. **排线金手指朝板内**，插到底并压下卡扣——黑屏 90% 是没插到底，不是驱动问题。
2. **不热插拔**排线（断电再动）。
3. 供电用 **5V/2A 独立电源**；插上 IO 底板后 **USB-NCM 失效**，只能走 RJ45（本项目 `192.168.5.0/24`）。

### 3.2 板端核对

```bash
uname -a
cat /etc/os-release
cat /proc/device-tree/model 2>/dev/null
dmesg | grep -iE 'gc2083|sensor|mipi|csi|vi' | tail -20
ls /mnt/system/usr/bin | grep -iE 'camera|sensor|sample|rtsp'
```

> ⚠️ **更正**：原稿写"`ls -l /dev/video*` 有节点说明驱动挂上"——**Duo 没有 `/dev/video*`**。
> 它走 Cvitek VI 管线（MMF 框架），不是 V4L2。判据改为 `dmesg` 里的 `sensor_0 init_done`。

### 3.3 取图（**以 §四 实测为准**）

```bash
# 板端起推流（本镜像开机自启，通常无需手动执行）
ps | grep sample_vi | grep -v grep
# 若未启动：
setsid sh -c 'cd /root && camera-test.sh </dev/null >/root/cam.log 2>&1' &
```

```powershell
# PC 侧拉流（VLC；用 TCP 更稳，避免 UDP 丢包导致画面卡死）
& "C:\Program Files\VideoLAN\VLC\vlc.exe" --rtsp-tcp "rtsp://192.168.5.9/h264"
```

> ⚠️ **更正**：原稿的 `rtsp://...:8554/stream` 与 `scp ...:/root/sample.jpg` 都不对——
> 实际是 **`rtsp://192.168.5.9/h264`（端口 554）**，且 `camera-test.sh` **不保存图片**，样张只能靠 VLC 截图。

## 六、坑（已踩过的记在这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| 全黑 / 花屏 | 排线没插到底、金手指朝外 | 断电重插，压卡扣 |
| 板子 ping 不通 | 插了 IOB 底板，USB-NCM 失效 | 走网口，确认 PC 与板同网段 |
| `ls /dev/video*` 空 | **正常**，Duo 无 V4L2 节点 | 用 `dmesg \| grep init_done` 判断 |
| 手动跑 `camera-test.sh` 报 `0xc0068004` | 开机自启实例已占 VPSS | `kill <PID>`（**不加 -9**）后再起；泄漏只能 `reboot` |
| **关掉 SSH 窗口后推流停止** | 前台进程随终端退出（SIGHUP），且不清理 VPSS | 用 `setsid sh -c '...' </dev/null &` |
| 画面卡住后 VLC 退出 | RTSP 走 UDP 丢包 | VLC 加 `--rtsp-tcp`；缓存设 200–1000 |
| 跑一会儿断了 | 供电不足或过热 | 独立 5V/2A；看 `thermal_zone` |
