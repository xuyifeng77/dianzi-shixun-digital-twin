## 二、这一步为什么关键

排线、MIPI 通路、sensor 供电、镜像自带的 GC2083 驱动——**任一环错都不出图**。出图即同时证明这四件事都对上了，后面所有 TDL 推理都建立在这条通路上。所以这是 B 岗第一个真正的里程碑，也是"板子能用"的第一个硬证据。

## 三、复现步骤（别人照做也能出图）

### 3.1 硬件三点

1. **排线金手指朝板内**，插到底并压下卡扣——黑屏 90% 是没插到底，不是驱动问题。
2. **不热插拔**排线（断电再动），sensor 供电由板子给，热插容易打坏 CSI。
3. **供电用 5V/2A 独立电源**；插上 USB&Ethernet IO 底板后 **USB-NCM 网卡失效**，此时只能走网口访问（本项目按 `192.168.5.0/24` 网段）。

### 3.2 板端核对（输出贴到 §四）

```bash
uname -a
cat /etc/os-release
cat /proc/device-tree/model 2>/dev/null          # 应看到 milkv / duo256m 字样
dmesg | grep -iE 'gc2083|sensor|mipi|csi|vi' | tail -20
ls -l /dev/video* /dev/media* 2>/dev/null        # 有节点说明驱动挂上了
ls /mnt/system/usr/bin | grep -iE 'camera|sensor|sample|rtsp'
```

判读口径：

- `dmesg` 里有 `gc2083` / sensor 探测成功、`/dev/video*` 存在 → 驱动层 OK，问题只可能在取图程序。
- 两者都没有、`dmesg` 干净得像没插摄像头 → 先回去查排线，别改代码。

### 3.3 取图（两种，按需选）

```bash
# A. 板端直出存图（实际执行的命令以 §四 记录为准）
cd /mnt/system/usr/bin && ./camera-test.sh        # 或镜像里的 sensor/sample 演示程序
# 产出样张后取回：
scp root@192.168.5.7:/root/sample.jpg .
```

```bash
# B. 网络拉流（β 架构与答辩演示用；地址以 §四 实测为准）
ffplay -fflags nobuffer -flags low_delay rtsp://192.168.5.7:8554/stream
```

## 六、坑（已踩过的记在这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| 全黑 / 花屏 | 排线没插到底、金手指朝外 | 断电重插，压卡扣 |
| 板子 ping 不通 | 插了 IOB 底板，USB-NCM 失效 | 走网口，确认 PC 与板同网段 |
| 板上 `ls /dev/video*` 空 | 驱动未加载 / sensor 未识别 | `dmesg` 看 probe，别先怀疑程序 |
| 流看着卡 | 解码/网络抖动，非采集问题 | 先本地存图确认采集正常，再查网络 |
| 跑一会儿断了 | 供电不足或过热 | 独立 5V/2A；摸散热片，看 thermal |
