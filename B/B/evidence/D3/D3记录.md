## 一、`camera-test.sh` 全文（就两行有效内容）

```sh
#!/bin/sh
export LD_LIBRARY_PATH=/mnt/system/lib:/mnt/system/usr/lib:/mnt/system/usr/lib/3rd
sample_vi_fd /mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel
```

**结论：这个脚本 = 设置库路径 + 跑 `sample_vi_fd`。** 没有别的魔法。

## 四、板上有的两个模型

```
/mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel              ← 人脸检测（在用）
/mnt/cvimodel/mobiledetv2-pedestrian-d0-ls-448.cvimodel   ← 行人检测（未用）
```

> 📌 **给 A 的一个建议（由他决定，别自己改）**：
> 我们有"行人检测"模型，但用的是"人脸检测"。区别在于：**背对摄像头的人，人脸检测会漏，行人检测不会**。
> 实验二（计数准确率）里"侧身/背向"这一组，用人脸检测的漏检率可能偏高。
> 两个选择：① 保持现状，报告里把"以人脸计数，背向会漏"写成已知局限；② 换行人检测模型再测一轮。
> **这不是我能单方面决定的，D3 记录里提出来，让 A 在 D4 前拍板。**

## 六、一个重要发现：板子**开机自启** `sample_vi_fd`

- 重启后立刻 `ps`，就有一个 `sample_vi_fd /mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel`（PID 289）
- 也就是说：**开机后 RTSP 流已经在推了，不需要再跑 `camera-test.sh`**
- 直接跑 `camera-test.sh` 会失败（VPSS 组 0 被占，`0xc0068004`）
- 要用自己的实例：先 `kill <PID>`（**不能 `kill -9`**，会泄漏 VPSS，只能重启恢复）
- 待查：是哪个启动脚本拉起的（`grep -rl "sample_vi_fd" /etc /mnt/system`），查出后写进操作手册
