## 五、踩到的三个坑（写进报告"节点实现"章节）

### 坑 1 · 板子**开机自启** `sample_vi_fd`，手跑 `camera-test.sh` 必失败

- **现象**：`CVI_VPSS_CreateGrp(grp:0) failed with 0xc0068004!` → `init middleware failed!`
- **原因**：系统启动时已经有一个 `sample_vi_fd` 实例在跑（PID 289，重启后立刻存在），VPSS 组 0 被它占着
- **处置**：
  - **首选**：直接用开机实例——端口 554 已经通，VLC 直接拉流，**不需要再跑 `camera-test.sh`**
  - 若确实要自己跑：先 `kill <PID>`（**不能用 `kill -9`**）把自启实例停掉

### 坑 2 · `kill -9` 会泄漏 VPSS 资源，只能重启恢复

- **现象**：`kill -9` 杀掉进程后再启动，仍然报 `0xc0068004`
- **原因**：`-9` 不给程序执行清理的机会（正常退出会打印 `destroy middleware` / `stop VPSS`）
- **判定**：看日志里有没有 `handle signal, signo: 15` 后的 `destroy middleware`
- **正确做法**：前台按 `Ctrl + C`，或 `kill <PID>`（SIGTERM）

### 坑 3 · `ls /dev/video*` 报错是正常的

- `No such file or directory` 不代表摄像头坏
- Duo 的摄像头走 **Cvitek VI 管线（MMF 框架）**，不是 V4L2，本来就没有 `/dev/videoN`
- 正确判据：`dmesg | grep -i -E "sensor|vicap"` 里有没有 `sensor_0 init_done`

## 六、取图方式（A 第 3 条要求的回填）

**板号**：☑ A 板（`milkv-a`，`192.168.5.9`）

**完整步骤**（可复现）：

| 步 | 在哪 | 命令 / 动作 |
|---|---|---|
| 1 | 板子 | `ps \| grep sample_vi \| grep -v grep` —— 确认 `sample_vi_fd` 在跑（开机自启） |
| 2 | 板子 | 若不在跑：`setsid sh -c 'cd /root && camera-test.sh </dev/null >/root/cam_a.log 2>&1' &` |
| 3 | 电脑 | VLC → 媒体 → 打开网络串流 → `rtsp://192.168.5.9/h264` |
| 4 | 电脑 | 显示更多选项 → **缓存 200 ms** → 播放 |
| 5 | 电脑 | 人站到镜头前，等画面出现**青色人脸检测框** |
| 6 | 电脑 | `视频 → 快照`（或 `Shift+S`）保存 |

**取图命令（终端一侧）**：

```powershell
# 1) 确认端口可达
Test-NetConnection 192.168.5.9 -Port 554

# 2) 命令行拉流（也可用它替代 VLC GUI，截图需另配）
& "C:\Program Files\VideoLAN\VLC\vlc.exe" --rtsp-tcp "rtsp://192.168.5.9/h264"
```

> 用 `--rtsp-tcp` 是为了避开 UDP 丢包导致的画面卡死（本项目实测踩过）。

**样张**：[`样张_带人脸框.png`](样张_带人脸框.png) —— 画面中可见人脸检测框，标题栏显示流地址 `rtsp://192.168.5.9/h264`。

> 这张才**同时**证明了"摄像头出图"与"人脸检测在跑"；
> 早先那张 `样张_VLC出图.png` 拍的是天花板空画面，只能证明前者。
