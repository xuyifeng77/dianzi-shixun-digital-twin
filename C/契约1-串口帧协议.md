# 串口帧协议 ASCII v1.1（契约 1）

> 责任人：C 起草 ｜ 冻结：v1.0 = 2026-11-24（D2）；v1.1 = 同日，仅追加 `rst` 字段 ｜ 签字：A
> 出方：C（UNO 固件 `UNO_Node.ino` v1.2）→ 用方：B（`duo_bridge.py`）、D（看板/入库）
> 本协议是**唯一在跑的一套**。`02 §4.2` 的二进制帧（`0xAA55+LEN+TYPE+CRC16`）与 `03 §7` 的扩展类型标为"设计预案，未采用"，理由见 §7。

---

## 1 物理层

| 项 | 值 |
|---|---|
| 链路 | UNO D0/D1 ──USB 数据线──> Duo USB-A（host 模式） |
| 设备名 | 正品 UNO（ATmega16U2）= `/dev/ttyACM0`；CH340 克隆板 = `/dev/ttyUSB0`。**两端都必须自动探测，不许写死** |
| 参数 | 115200 bps，8N1，无流控 |
| 编码 | ASCII（纯文本行），`\n` 结尾；`\r` 容忍但不必发 |
| 最大帧长 | 32 字节（UNO 侧缓冲 48 字节，超长整帧丢弃） |

---

## 2 帧语法

```
'@' <TAG> [ ',' <字段> ]* '\n'
```

- 首字节必须是 `@`；不以 `@` 开头的行一律忽略（不回应、不动作）。
- 字段用半角逗号分隔，**不做转义、不做转义**，字段内不得含逗号。
- 帧尾 `\n`（0x0A）。
- 无校验和、无序号、无重传 —— 见 §7 的认账。

---

## 3 上行帧（UNO → Duo）

| 帧 | 格式 | 频率 | 字段与单位 |
|---|---|---|---|
| 环境 | `@E,t,h,smoke,flame,light,sound,rst` | 2000 ms 定时 + 收到 `@Q` 立即 | `t` 摄氏温度，1 位小数（`25.3`）；`h` 相对湿度 %，1 位小数；`smoke`/`flame`/`light`/`sound` = PCF8591 原始值 0–255；`rst` = MCUSR 原始字节 0–15 |
| 门磁 | `@D,0\|1` | 状态变化时（40 ms 稳定后） | 0 = 关，1 = 开 |
| 计数 | `@C,<n>` | 每次遮挡沿 | `n` 累计人次（uint16，上电清零，不回绕处理） |
| 刷卡 | `@R,<UID>` | 每次读卡 | UID 十六进制大写，4 字节卡 = 8 字符（如 `A1B2C3D4`） |
| 报警 | `@A,<lv>,<src>` | **等级变化时**（不重复发） | `lv` ∈ {0,1,2}；`src` ∈ {`NONE`,`SMOKE`,`FLAME`,`TEMP`} |

**样例**

```
@E,25.3,45.0,12,3,88,7,0
@D,0
@C,17
@R,A1B2C3D4
@A,2,SMOKE
```

`rst` 位义（AVR MCUSR）：`0x01` POR 上电 / `0x02` EXTR 外部复位 / `0x04` BOR 欠压 / `0x08` WDR 看门狗。

> **v1.1 的唯一改动**：`@E` 末尾追加 `rst`。旧解析器（`len(f) >= 6`）不受影响，新解析器可白拿"这台设备是否死机重启过"的证据链。B/D 侧不用改代码，但要登记契约版本。

## 4 下行帧（Duo → UNO）

| 帧 | 语义 | 合法范围 | 非法时行为 |
|---|---|---|---|
| `@L,<ms>` | 开锁 ms | **500 ≤ ms ≤ 10000** | 短帧 / 负数 / 0 / 越界 → 只响拒绝音，**继电器与舵机不动** |
| `@Q` | 心跳：立即回一帧 `@E` | — | — |
| `@Z` | 静音切换 | — | — |
| `@M,<0\|1>` | 演示模式（1 = 报警不断电） | 0 / 1 | 缺参数则忽略 |
| 其他 `@X` | 未知命令 | — | 忽略，不回应 |

**安全铁律（写进报告）**：坏帧必须**拒绝**，不能"钳位救场"。v1.1 的 `min(ms,10000)` 会把 `@L,-1` 变成一次 10 s 开锁，方向正好反了；v1.2 改为范围检查后 `denyBeep()`。

## 5 时序与超时

| 项 | 值 | 依据 |
|---|---|---|
| `@E` 周期 | 2000 ms | 带宽预算：单帧 ≈45 B → ≈180 B/s |
| Duo 心跳 `@Q` | 每 10 s | `duo_bridge.py` v1.2 `HB_INTERVAL` |
| 桥接判死 | 35 s 无回执 | `HB_TIMEOUT`，打印 `[LINK] DEAD`，**不退出** |
| 固件判死 | 15 s 无任何 `@` 帧 | LCD 显示 `LINK LOST`；**不改变继电器/舵机状态** |
| 断链报警时延 | 待测（C D8，拔 USB ×10 取中位数） | 这是"边缘自治"最硬的数字 |

当前结果：**18 项通过 / 0 失败**，覆盖：

## 7 为什么保留 ASCII 而不是二进制帧（答辩要能一句话说清）

**选择**：ASCII 行帧，无 CRC。

**理由**：现场可读、`cat` 串口就能看、抓包不用解二进制；调试成本几乎为零，而这套东西要在 10 天内由 4 个人联调。

**代价（必须认账）**：没有 CRC，单比特翻转会被当成合法值。缓解手段是"20 cm 板内 TTL + 变化上报（`@A`/`@D` 不重复发）+ 字段范围校验"。若将来链路变长或进工业环境，第一步就是换回 `02 §4.2` 的二进制帧 + CRC16/MODBUS。
