# 单节点物联网终端 · 项目说明书

> 面向课程验收 / 报告排版。配套文件：`00-傻瓜式组装教程.md`（怎么装）、`README-接线与排障.md`（怎么修）、`电路图.svg`（接线全图）、`UNO_Node/UNO_Node.ino`（固件）、`duo_bridge.py`（网关）。

---

## 1 项目概述

一套由**创乐博 CLB Arduino UNO R3 IOT SUPER 套件**（51 项）搭建的边缘物联网终端：以 **Milk-V Duo** 为语义层、**UNO R3** 为物理层，实现"环境监测 → 分级报警 → 门禁联动 → 数据上云"的闭环，并在 **AI 感知失效时仍能安全运行**。

| 项目档案 | |
|---|---|
| 硬件平台 | Arduino UNO R3 + **Milk-V Duo 256M（SG2002 / 256MB）** + IO 底板 + GC2083 摄像头 |
| 套件 | CLB UNO R3 IOT SUPER（51 项，核心 29 项） |
| 引脚占用 | 16/16 已满（D0/D1 留给 USB） |
| 通信 | UNO ⇄ Duo：USB 串口 115200，ASCII 帧协议 |
| 代码规模 | UNO 固件 1 份（16 分区）+ Duo 桥接 1 份（Python） |
| 额外物料成本 | ≈ 15 元（独立 5V/2A 电源、USB 转杜邦线） |
| 复现时间 | 熟练 1.5 h / 首次 2.5 h |

> ⚠️ **本说明书按"UNO 直插 Duo USB-A（Duo 为 host）"编写**，该路径需上机验证（切 `usb-host.sh` 后看 `ls /dev/ttyUSB*` 是否出现），详见 `可行性验证报告.md` §风险与退路。若不通，改用底板四针串口 + 1k/2k 分压，接线与协议不变。

## 2 问题与目标

**三个痛点**

1. 市售烟感只响不停机、只停不通风——**报警与处置脱节**；
2. 纯树莓派方案"视觉一挂全挂"，**感知层故障直接传导到执行层**；
3. 教学套件引脚有限，"功能全"与"接线可复制"难两全。

**三个目标**

- 报警必须**分级**：注意级排烟、危险级断电，误报不得一刀切停机；
- 系统必须**失效安全**：断电、复位、通信中断均回到安全态；
- 单套器材可复现，且**能长成集群**（加节点不改代码）。

**非目标（明确不做）**：自研视觉算法、云端大屏、多机同步推理。

## 3 系统架构

```
┌────────────── 语义层 Milk-V Duo ──────────────┐
│  GC2083 摄像头 → 人数计数 / 卡号白名单        │
│  NTP 时间戳 · 规则判定 · HTTP 上报            │
└───────────────┬───────────────────────────────┘
                │ USB 串口 115200（ASCII 帧，只传结论）
┌───────────────┴───────────────────────────────┐
│             物理层 Arduino UNO R3              │
│  采集：DHT11 / DS18B20 / MQ-2 / 火焰 / 光敏 /  │
│        声音(经 PCF8591) / U 型光电 / 干簧管     │
│  决策：分级状态机 + 去抖 + 预热屏蔽            │
│  执行：蜂鸣器 / 7 色 LED / 继电器 / 风扇 / 舵机 │
└────────────────────────────────────────────────┘
```

| 层 | 职责 | 归它管 | 不归它管 |
|---|---|---|---|
| Duo | 语义、策略、上云 | 谁、几个人、时间 | 阈值安全逻辑 |
| UNO | 物理事实、联锁 | 有无危险、该切断谁、门开不开 | 身份判定 |

**关键设计**：两者只交换**结论**而非原始数据。拔掉 Duo，UNO 的本地报警与门禁逻辑照常工作——**感知可降级，联锁不降级**。

## 4 硬件清单与引脚分配

| 引脚 | 模块 | 类型 | 说明 |
|---|---|---|---|
| D2 | DHT11 模块 | 数字 | 模块自带 10kΩ 上拉 |
| D3 | DS18B20 模块 | 数字 | 模块自带 4.7kΩ |
| D4 | **有源**蜂鸣器（必须） | 数字 | 节奏编码（危险 1s/1.5s，注意 0.15s/3s）；无源模块需 2–5 kHz 方波，不适用 |
| D5 | 7 色 LED 模块 | 数字 | 状态色 |
| D6 | 继电器模块 | 数字 | **低电平吸合**，常吸合给负载供电 |
| D7 | 舵机 SG90 | PWM | 门锁，独立 5V/2A |
| D8 | IR 接收头 | 数字 | IRremote ≥4.0 |
| D9 | 风扇（经 S8050） | 数字 | Servo 独占 Timer1，故不能用 analogWrite |
| D10–D13 | RC522 RFID | SPI | **3.3V 供电** + BSS138 电平转换 |
| A0 / A1 / A2 | U 型光电 / 干簧管 / 触摸 | 模拟转数字 | 计数 / 门磁 / 手动确认 |
| A4 / A5 | I2C：PCF8591(0x48) + LCD1602(0x27/0x3F) + OLED(0x3C) | I2C | 三从机并联 |
| D0 / D1 | — | — | 预留 USB 串口 |

**未接的两项及理由**：DS1302（引脚已满，时间戳由 Duo NTP 统一打）；无源蜂鸣器（**D4 必须装套件第 19 项有源模块**；无源需 2–5 kHz 方波，`tone()` 占 Timer2 与 IRremote 冲突，故三级语义改由有源模块的**节奏编码**承担，见 `13-决策记录` D-01）。

## 5 电气设计要点

1. **失效安全**：继电器线圈常吸合为台面负载供电，危险时释放→断电；**UNO 自身供电绝不串入触点回路**，否则报警即成自锁。
2. **驱动隔离**：风扇经 S8050 低边开关，基极串 1kΩ，风扇两端反并 1N4007 抑制反电动势。
3. **电源分域**：5V 供逻辑、3.3V 仅供 RC522、独立 5V/2A 供舵机与风扇，**三域共地一点连接**。
4. **电平匹配**：RC522 是 3.3V 器件，SPI 必须经 BSS138 四路转换，严禁 5V 直连。

## 6 软件设计

### 6.1 串口协议（ASCII，`@` 开头，逗号分隔，`\n` 结尾）

| 方向 | 帧 | 含义 |
|---|---|---|
| UNO→Duo | `@E,t,h,smoke,flame,light,sound` | 环境帧，2 s 一次 |
| UNO→Duo | `@D,0\|1` | 门磁状态 |
| UNO→Duo | `@C,<人次>` | 计数 |
| UNO→Duo | `@R,<UID>` | 刷卡请求 |
| UNO→Duo | `@A,<0\|1\|2>,<来源>` | 报警等级与来源 |
| Duo→UNO | `@L,<ms>` | 授权时长（0=拒绝） |
| Duo→UNO | `@Z` / `@Q` / `@M,<0\|1>` | 静音 / 立即回帧 / 演示模式 |

**铁律：串口只跑协议，调试一律走 LCD/OLED**，避免日志污染帧解析。

### 6.2 分级状态机与阈值

| 量 | 注意级 L1 | 危险级 L2 | 动作 |
|---|---|---|---|
| 烟雾 | 120 | 200 | L1 通风排烟 / L2 断电+长鸣 |
| 火焰 | 150 | 250 | 同上 |
| 温度 | — | 45.0 ℃ | L2 |
| 预热 | `WARMUP_MS = 30000` | — | MQ-2 预热期屏蔽报警 |

### 6.3 非阻塞调度

| 任务 | 周期 |
|---|---|
| 采样 | 1 s |
| 报警判定 / 去抖 | 1 s |
| 上报 | 2 s |
| LCD 刷新 | 500 ms |

全固件**无 `delay()`**，任何一路慢操作不会拖死报警响应。

## 7 创新点

| # | 创新点 | 常规做法 | 本项目 | 验证方式 |
|---|---|---|---|---|
| 1 | 异构双核分层 | 单板全包 | Duo 给语义、UNO 给物理事实，只传结论 | 拔掉 Duo，本地报警与门禁仍工作 |
| 2 | 失效安全默认态 | 报警时输出动作 | 继电器常吸合，危险时释放断电 | 断电/复位即安全态 |
| 3 | 分级而非布尔 | 超阈值一律动作 | 0/1/2 级 + 来源编码 | 误报只降级不误停 |
| 4 | 策略上移 | 卡号/阈值写死固件 | 白名单在 Duo，阈值集中宏 | 换卡 30 s 生效 |
| 5 | 协议可扩 | 单机硬编码 | 帧格式统一，加节点只增编号 | 再配 3 套即 4 节点集群，代码不改 |

> 表述口径：属**集成创新 / 工程取舍**，非算法首创。局限：视觉用现成模型，创新集中在系统架构与安全逻辑。

## 8 实施与测试

**实施六阶段**（详见装配教程）：认针脚 15 min → 传感器 30 min → 显示执行 30 min → 两个小电路 40 min → 软件上传 20 min → 联调验收 25 min。

**验收判据**

| # | 判据 | 标准 |
|---|---|---|
| 1 | 正常态 | 继电器吸合、风扇停、绿灯 |
| 2 | 烟雾报警 | 放气后 ≤3 s 转风扇 + 长鸣 + 断电 |
| 3 | 明火报警 | 明火靠近立即 L2 |
| 4 | 门禁 | 授权卡开锁 3 s 回锁；非法卡两声短鸣 |
| 5 | 鲁棒性 | 掉电重上电 30 s 内自动恢复；拔 Duo 不影响本地联锁 |

**性能口径**：报警响应 <3 s（以串口帧 `@A` 时间戳计）；单节点计数标定 **120 人次**（12 组 × 10 人次），误计 ≤2%。

## 9 局限与展望

- **局限**：单节点、单卡白名单、无本地持久化；视觉依赖光照；RC522 读距约 3 cm。
- **下一步**：①加 3 节点组集群（协议已支持）；②卡号改存 Duo 端 SQLite；③温度用 PID 联动排风调速（需换非 Servo 引脚）。
